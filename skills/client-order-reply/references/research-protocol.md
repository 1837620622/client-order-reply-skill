# 需求精读与全网联网查证 SOP

接单最容易露馅、报亏、或者写出一股 AI 味的两个根源：一是没把客户要求看透就急着回，二是对不熟的专业领域凭印象胡扯。动笔之前必须按本流程过一遍。

## 一、三遍精读法（不漏隐含条件）

拿到用户丢过来的聊天记录、截图、PDF、Word、Excel、代码或工程文件后，至少读三遍：

### 第一遍：扫清全貌与现场
- 看完整对话链路：客户最初提了什么、中途改过什么、用户前面回复过什么（避免前后口径打架）、用户这次额外交代了什么策略要求。
- 读透全部附件：
  - 截图/聊天图：从上到下逐行读清每一个参数、报错码、指标名、批注、截止日期，不放过边角小字。
  - 任务书/开题报告/审稿意见：抓核心目标、硬性考核指标、字数/图表/格式要求。
  - 代码/数据/模型文件：能直接打开查看的就打开看变量名、样本量、缺失情况、模块拓扑、软件版本号和报错堆栈，看到真东西再张嘴。
- 识别客户画像：
  - 本科毕设/课程作业：通常对工具和理论不深，更在意能跑通、图好看、看得懂、答辩能应付，容易低估数据清洗和调参工作量。
  - 硕博论文/期刊投稿：看重方法规范性、前沿审稿要求（如内生性、稳健性、消融实验、网格无关性）、可复现性，一说外行话立刻掉信任。
  - 企业/工程/量化实盘：看重真实工况、边界合规、国标/行标、交付稳定性与落地时间，讨厌学院派空话。
  - 竞赛（美赛/国赛/电赛等）：极度卡死线，看重完整闭环与结果合理性。

### 第二遍：挖隐含工作量与雷区
把“客户没明说，但干活必须做”的账全翻出来：
- **版本与环境约束**：指定 MATLAB R2022b、Stata 17、PSIM 2022、PowerFactory 2023、Python 3.10、CUDA 版本等，高低版本打不开或包冲突全是工时。
- **数据来源黑洞**：客户说“数据自己找一下就行”，实际可能要 Wind/CSMAR 会员权限、手工翻几十份地方统计年鉴、反爬抓取、跨库代码匹配、处理 ST/金融股/退市/口径变更。
- **隐性验证与配套活**：
  - 金融实证：往往不只跑个基准回归，后面跟着平行趋势检验、PSM-DID、安慰剂检验、工具变量、异质性、机制检验、缩尾和替换变量。
  - 仿真建模：往往不只搭出模型能运行，还要扫频、多工况对比、故障点逐一校核、与理论值/国标对比、网格/步长无关性验证。
  - 算法模型：往往不只跑通源码，还要换自己的数据集、做数据标注、配环境修报错、跑 3 到 5 个 Baseline 对比、做消融实验和可视化。
  - 配套交付：要不要写分析文字、要不要画论文规范三线表/高分辨率图、要不要帮配环境（默认不远程，改好发文件再口头讲）、要不要录屏或语音讲解答疑、要不要跟着导师意见改几轮。
- **找出矛盾与缺口**：记下客户没说清楚的关键信息（如样本年份、核心变量定义、边界条件、目标指标、到底要源码还是只要结果），挑最关键的 1 个问题在回复里自然问出来。

### 第三遍：判局势与真实意图
- 判断客户目前的心态：是广撒网比价、拿着低价截图来压价、自己改现成代码改崩了来救火、还是懂行在试探你水平。
- 判断现在该推进哪一步：
  - 信息严重不足 → 先要文件/明确核心口径，不急着大段输出。
  - 客户在试探水平 → 精准点出 2 到 3 个只有真干过才知道的实操坑，点到即止。
  - 客户拿现成方案/低价对比 → 用真实技术差异把风险讲透，不贬损同行，只讲事实。
  - 客户催着报价但用户没让报 → 借核对细节和工作量自然稳住，让对方先发资料或先说预算。

## 二、强制全网搜索与知识核实

只要出现以下任一信号，**禁止凭记忆猜，必须立刻联网搜索查证**（调用当前助手可用的 Web Search、网页抓取、文档查询或 MCP 搜索工具）：

| 触发场景 | 必须搜什么 | 搜完怎么用 |
| --- | --- | --- |
| 陌生模型/算法/计量方法 | 标准定义、主流实现包/命令、必备输入数据、最新学术审稿争议点、常见不收敛/不显著坑 | 在回复里准确叫出工具/检验名，点出真正的难点，不露外行怯 |
| 特定数据库/指标口径 | 该指标在 CSMAR/Wind/CNRDS/WRDS 等库里有没有现成字段、覆盖年份、常见缺失或跨库匹配方式 | 准确判断要不要手工补数或写爬虫，避免接下隐形苦力单 |
| 国标/行标/监管/赛事规则 | 现行有效版本号、关键考核指标范围（如高低穿考核曲线、会计新准则生效年份、期刊复现政策） | 用准确口径和客户对齐验收标准，绝不拿旧标准瞎说 |
| 软件报错/兼容性/算力需求 | 报错真实诱因、模型对显存/核数/软件模块的要求、常见排查顺序 | 给出直击要害的排查思路，一眼立住高手形象 |
| 需要核价但对该细分单没把握 | 同类任务的常见市场行情、常规工序耗时、高门槛细分项的溢价情况 | 给用户提供经得起推敲的工作量与报价区间，不报低亏死也不报虚 |

### 搜索技巧与防坑
- **优先查一手源**：官方文档（MathWorks、Stata、PowerFactory、PyTorch、ANSYS、QuantConnect）、顶刊论文/教材方法说明、权威行业标准、GitHub Issue、Statalist/知乎/专业社区的实操讨论。
- **关键词要具体**：别只搜“金融实证怎么做”，搜 `"多期DID" "异质性处理效应" "csdid" 审稿`、`"CSMAR" "华证ESG" 覆盖年份 缺失`、`"GB/T 19964" 高低电压穿越 测试点`、`"PSIM" "AC Sweep" "LLC" 偏差`。
- **双源核对**：关键参数、标准要求、行情价位尽量核对两个独立来源；营销号和过时老帖不直接采信。
- **绝不把搜索过程暴露给客户**：查完吸收成自己的行家判断，回复里用自然口语点出核心结论，不写“根据我查询到的资料显示”。

### 无联网环境或查不到时的红线
- 严禁脑补标准号、命令参数、数据库字段、现成论文代码能否跑通。
- 查不到或没联网时：给客户的回复只讲有十足把握的通用实操与需要核对的地方，顺势让客户把参考论文、任务书、原始数据或报错截图发过来；同时在回复框外如实告诉用户“某某细节未联网核实，拿到对方文件后再确认”。
